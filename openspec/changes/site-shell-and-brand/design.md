## Context

- The header (`AppHeader.vue`) draws a hand-made inline SVG spiral with a gradient and the text "Align**OS** *Reader*". Its nav array has one live item (Codex Lattice → `/`); FAQ and About are commented out.
- `index.html` links `/favicon.svg`, titles the site "Codex Lattice | Align OS", and names it "AlignOS Codex Lattice" in JSON-LD.
- `AppFooter.vue` already has the footer quote and `mailto:info@alignos.io`.
- Brand masters in `client/public/`:
  - `alignos-spiral.png` is 624×624 and 95 KB, gold brush spiral on transparent.
  - `alignos-logo-text.svg` is 3.6 KB with seven vector paths: gray `#8C8B92` letters and a gold `#F2C32F` dot. It declares `width="3631" height="897"` but **no `viewBox`**, so CSS sizing crops it.
  - `alignos-logo-text.png` is 400×99.
- Routes are `/` (lattice, named `browse`), `/codex/:id`, `/search`, plus a catch-all to `/`.
- `vite.config.js` `includedRoutes` pre-renders `/faq` and `/about`, which are not routes.
- `vercel.json` redirects are generated by `scripts/generate-redirects.js` from provenance `id_change` rows plus one static `/about` → `/` rule. The generator overwrites the `redirects` array wholesale.
- The WordPress capture (`analysis/legacy-pages/`, gitignored) lists the page sitemap and every PDF link on the lattice and pages (134 lattice PDFs plus Papers/home variants). Ripple post URLs were mapped but not saved.
- Styling direction (Ron): reuse the existing SCSS theme (`client/src/assets/scss/_variables.scss`, `--cl-*` tokens, light and dark). The WordPress site contributes only the logo.

## Goals / Non-Goals

**Goals:**
- Brand lockup and favicon from the supplied masters, sized like today's header.
- One route table and one nav definition, so `legacy-pages-and-collections` only has to fill in page bodies.
- A redirect map that is reviewable data, with generation that fails loudly on gaps.

**Non-Goals:**
- Page content (home, Return Room, Papers, etc.). That belongs to `legacy-pages-and-collections`.
- `llms.txt` and the AI layer. That belongs to `ai-orientation-layer`. The footer link falls back to `/llms.json` until it exists.
- Deployment, DNS cutover, Blob migration. That belongs to `vercel-deployment-bootstrap`, deferred.
- Redrawing or recoloring the logo.

## Decisions

### D1. Lockup is two `<img>` elements, not inline SVG
The spiral is a raster brush stroke and can't become a clean SVG without redrawing it, which Ron ruled out. The wordmark SVG is small enough to reference directly.
- Fix `alignos-logo-text.svg` once in place: add `viewBox="0 0 3631 897"` and remove the fixed `width`/`height`. Paths are already offset by the inner `translate(-236 -1422)`, so `0 0 3631 897` is the correct box.
- Generate `client/public/brand/alignos-spiral-72.png` and `-108.png` (2× and 3× of 36px) with `sharp`, which is already a root dependency, and serve them via `srcset`.
- Keep the masters untouched as the source for future derivatives.
- *Alternative:* inline the wordmark SVG with `currentColor` so it could recolor per theme. Rejected for now: the gray `#8C8B92` reads on both the warm light and dark surfaces, and Ron wants the logo kept as supplied. Revisit only if the contrast check (task 2.4) fails.

### D2. Favicon generated by a script, committed as output
`scripts/generate-favicons.js` (sharp plus a small ICO writer, or the `png-to-ico` package) produces `client/public/favicon.ico` (16/32/48) and `apple-touch-icon.png` (180, with the spiral padded on a transparent canvas). Outputs are committed, so the build doesn't depend on image tooling.

### D3. Named routes; the lattice is `lattice`
Rename route `browse` to `lattice` at `/lattice`, and switch in-app links to `{ name: 'lattice' }` so future path moves don't touch views. Add routes for all pages in the spec's route map. Until `legacy-pages-and-collections` lands, they render a minimal pending view (title only). All four AlignOS 2.0 changes land before any staging deploy, so the pending view is never public. `includedRoutes` is built from the route table plus codex routes, which also fixes the stale `/faq` and `/about` entries.

### D4. Nav defined as data with one level of children
Turn `navItems` into `{ name, to, children? }`. Desktop renders children as a Bootstrap dropdown, and the parent is active when any child matches. On mobile, children are listed indented under the parent in the existing collapse; there's no nested toggle. Label is "Begin a Return Room": the WordPress "Begin an Return Room" was a typo, and the home CTA already says "a".

### D5. Legacy redirects: committed map plus the extended generator
- `data/legacy-urls.json` holds rows `{ source, destination, kind, note? }`.
- A one-time script, `scripts/capture-legacy-urls.js`, builds the first draft:
  - pages from the page sitemap
  - PDFs from the captured markdown links, matched to catalog ids by normalized filename against `provenance.old_cover_filename` and titles
  - ripple posts from a fresh fetch of the WordPress post sitemap
- Any match it can't make goes into an `unmatched` section that a human resolves. The committed JSON is the reviewed result. The capture script isn't part of the build.
- `generate-redirects.js` merges three sources into `vercel.json`: static rules, provenance id redirects, and `legacy-urls.json`. It de-duplicates by source and fails if `legacy-urls.json` has an `unmatched` section or a destination id that isn't in the catalog.
- *Alternative:* catch-all regex redirects such as `/wp-content/uploads/:path*` → `/`. Rejected because they lose the per-PDF destination, which is the whole value.

### D6. Evolution of the Sovereign compilation PDF
Rename `client/public/pdf/The-Evolution-of-the-Sovereign.pdf` to `the-evolution-of-the-sovereign.pdf` (kebab-case, matching the house pattern) so redirects and the home page can target it. Its identity as a series asset is formalized in `series-corridors-and-placeholders`.

### D7. Kimi K3 does the visual pass
Implementation is split:
- Structural wiring (routes, nav data, redirect scripts) is plain code.
- The visual pass on header and footer goes to a Kimi K3 (`kimi-k3-max`) subagent: lockup sizing and alignment, dropdown styling, mobile menu, and a contrast check in both themes.
- Kimi's brief: use only existing `--cl-*` tokens and SCSS partials, keep the header height, match today's hover and transition language, and add no new fonts or palettes.

## Risks / Trade-offs

- [Ripple sitemap may no longer be fetchable, or may include non-codex posts] → The capture records whatever the sitemap yields. Non-codex posts get kind `retired` → `/`. If the sitemap is gone, fall back to slug-matching the 134 lattice titles and note it in the map.
- [Vercel redirect count grows to roughly 100 id redirects + 140 PDFs + ~135 ripple + 5 pages] → That's well under Vercel's per-project route limits. The generator prints totals.
- [PDF destinations move if the Blob migration happens later] → Destinations are built from the same PDF base used by the app's URL builder. Re-running the generator after a base change updates every row.
- [Moving the lattice off `/` breaks stored scroll and back-navigation habits] → The lattice keeps its `lattice-position` storage key, and the home page links prominently to `/lattice`.

## Migration Plan

1. Land this change and `legacy-pages-and-collections` together, then build locally and preview.
2. The redirects only matter once alignos.io DNS moves (`vercel-deployment-bootstrap` 7.3, after James' review). Until then they're inert on the preview domain but testable there.
3. Rollback is a git revert. The masters and data files are additive.
