## Context

- `PageView.vue` renders `client/src/content/pages/{slug}.md` (eager `?raw` glob) through `parsePageMarkdown`, chosen by route meta `page`. Its click handler turns site-relative links into router navigation.
- The review documents live in `docs/review/` at the repo root, outside the Vite root (`client/`). `james-questions.md` is regenerated by `scripts/audit-series.js`; `alignos-2-review.md` is hand-written.
- `build-ai-layer.js` publishes only the pages in its fixed `PAGES` list, so new routes don't leak into `llms.txt` by default.
- `generate-redirects.js` rewrites only `vercel.json`'s `redirects` array.
- Staging is the Vercel project's production deployment (`alignos-omega.vercel.app`), so Vercel's environment name can't tell staging from the future alignos.io.

## Goals / Non-Goals

**Goals:**
- Review text is absent from production output, not merely unrouted.
- One source per document: the markdown files stay the source; the pages render them.

**Non-Goals:**
- Access control. The staging URL is unlisted and noindexed; Vercel Deployment Protection stays available if that's ever not enough.
- Any review-specific design. The pages use the standard page layout.

## Decisions

### D1. Build-time flag through `define`
`vite.config.js` defines `__ALIGNOS_REVIEW__` as `process.env.ALIGNOS_REVIEW === '1'`. The router appends the two review routes inside `if (__ALIGNOS_REVIEW__)`, and only that branch references the review view. With the flag off, the constant is `false`, Rollup drops the branch, and the view and its markdown are never emitted.
- `includedRoutes` already pre-renders every static route, so the review pages are pre-rendered when present.
- *Alternative:* a `VITE_ALIGNOS_REVIEW` variable read through `import.meta.env`. It also tree-shakes, but `define` keeps the Vercel variable's name free of the Vite prefix.
- *Alternative:* always build the pages and block them in `vercel.json` by host. Rejected because the text would still ship in the JavaScript of the live site.

### D2. A review view wraps PageView
`ReviewView.vue` loads `docs/review/*.md` with an eager `?raw` glob and passes the chosen document to `PageView` through a new optional `markdown` prop (falling back to today's `page` lookup). It sets `<meta name="robots" content="noindex">` via `useHead`. Route meta carries `review: 'alignos-2-review' | 'james-questions'`, a title, and `layout: 'standard'`.
- The dev server refuses files outside the Vite root unless allowed, so `server.fs.allow` adds `../docs/review` alongside the default workspace root.
- Maintainer notes become HTML comments, which the renderer passes through and the browser doesn't display.
- *Alternative:* copy the documents into `content/pages/`. Rejected because two copies drift, and the pages glob would put them in every build.

### D3. Links in the question list
`audit-series.js` gains `codexLink(id)` → `[*Title*](/codex/{id})` and links series headings to `/lattice?series={id}`. Every place that names a catalog codex uses it, including the edition, unplaced, and catalog-review sections. Planned works stay unlinked, since they have no page. File-and-line citations stay plain text; James can't open them, but they let him tell us where he saw something. The header blockquote becomes an HTML comment (D2).

### D4. Noindex by host
`vercel.json` gets a `headers` rule on `/(.*)` with `has: [{ "type": "host", "value": { "suf": ".vercel.app" } }]` setting `X-Robots-Tag: noindex`. This covers the production alias and every preview URL, and never matches alignos.io, so cutover needs no step for it. Review pages also carry the meta tag (D2), so they stay noindexed even if a build with the flag is served from a custom domain.

### D5. Flag lifecycle
Set `ALIGNOS_REVIEW=1` on the Vercel project's Production environment (that's the staging build today). `vercel-deployment-bootstrap` gets a task before the DNS move: remove the variable, redeploy, and confirm `/review` redirects home.

## Risks / Trade-offs

- [The flag is forgotten at cutover, so the review pages go live on alignos.io] → The cutover task and its smoke test. Even then the pages are noindexed, unlinked, and hold nothing private.
- [`breaks: true` page parsing renders single newlines as `<br>`] → Both documents put each paragraph and list item on one line; verify after rendering.
- [The question list is regenerated and overwrites hand edits] → All link formatting lives in the generator, not the file.

## Migration Plan

1. Land the change and set `ALIGNOS_REVIEW=1` on the Vercel project.
2. Push; verify `/review`, `/review/questions`, and the `X-Robots-Tag` header on staging.
3. Rollback is a git revert plus removing the variable.
